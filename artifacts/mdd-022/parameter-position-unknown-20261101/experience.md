# 参数注解编码槽与原型位置

- 现象：短参数注解列表的覆盖状态是 `Unknown`，但解析器曾将编码槽 `0` 的 `parameter_position_in_prototype` 输出为 `Some(true)`。
- 证据：`red/record.json` 的合成短列表测试实际失败；原始失败日志和源码摘要已保留。
- 根因：旧实现只检查槽序号是否小于原型参数数量，误将数值范围内当成已经证明的位置映射。
- 修正：仅当编码槽数量与原型参数数量相等时标记已知位置；不等时保留编码槽，位置为未知。类型化原始关系明确输出 `complete`、`unknown` 或 `not_applicable`，需要原型位置的查询仍须走完整性门禁。
- 失败方案：仅在新查询结果层遮蔽该值会留下既有原生 SQL 和其他事实消费者的误判，因此修正了事实源；不能用空结果或补齐空槽替代未知映射。
- 验证范围：`final/record.json` 为解析器与类型化局部检查，`sql-join-final/record.json` 为同源 occurrence／类／方法的 SQL 覆盖关联。直接反例仅为短列表；长列表、空列表和完整格式仍需独立验收。MDD-022 已重新打开，MDD-026 的依赖未满足，不能凭局部绿例恢复完成状态。
